# 阶段 0：业务范围与验收基线

**目标：** 为现有项目确定一个可验证的部门内部助手首发场景，避免继续扩张演示功能。

## 推荐首发场景

选择一个拥有稳定文档和明确负责人部门，例如研发效能、售前支持、采购运营或人力制度。首发只支持三类任务：

1. 带来源的制度/项目/产品资料问答；
2. 长文档与会议材料摘要；
3. 基于已授权资料生成邮件、工单或检查单草稿。

禁止自动发送、修改业务数据、创建订单、变更生产配置或代表公司对外承诺。

## 文件与交付物

- Create: `docs/business-scenarios/<department>/scenario-card.md`
- Create: `docs/business-scenarios/<department>/knowledge-register.csv`
- Create: `docs/business-scenarios/<department>/evaluation-set.md`
- Create: `docs/business-scenarios/<department>/access-matrix.md`

## 执行清单

- [ ] 指定业务负责人、知识内容负责人和安全负责人；三人共同拥有上线/停用权限。
- [ ] 在场景卡写明用户角色、三个任务、允许输入、禁止输入、允许输出、禁止输出、成功指标和人工处理路径。
- [ ] 建立首批知识登记表：文件名、来源链接、内容所有者、密级、所属部门/项目、发布日期、复审日期、审核状态。
- [ ] 从真实工作中收集至少 30 条脱敏任务：10 条正常问答、5 条过期资料、5 条权限不足、5 条无答案、3 条敏感信息、2 条提示词注入。
- [ ] 对每条任务写明预期行为、必要引用和不可接受的行为，而不是只写正确答案。
- [ ] 定义首发阈值：引用正确率、拒绝越权率、无依据回答率、人工改写率、p95 响应时延和每任务预算。

**退出条件：** 三名负责人批准场景卡；评测集和知识登记表冻结为 `v1`；未选定部门前不得上传真实企业资料。
